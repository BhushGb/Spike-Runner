# Spike Runner Player's Guide

This repository is a **learning and demonstration project** focused on applying the Microsoft Writing Style Guide to technical and user documentation.

It shows the practical difference between a casual player-facing guide and a version rewritten to follow Microsoft’s style rules for clarity, consistency, tone, and accessibility.

## Project Contents

| File | Description |
|------|-------------|
| **Casual_Guide.pdf** | Original user guide written in a casual, conversational style. Explains how to play *Spike Runner*. Created with the assistance of AI. |
| **MS_Style_Compliant_Guide.pdf** | Revised version of the casual guide, rewritten to comply with Microsoft Style Guide rules. |
| **Changelog** | Detailed record of all changes made when converting the casual guide into the Microsoft Style Guide–compliant version. |

## Purpose

- Demonstrate how to transform informal / casual documentation into professional, style-guide–compliant content.
- Practice and showcase skills related to the Microsoft Writing Style Guide (voice & tone, terminology, sentence structure, accessibility, formatting, etc.).
- Serve as a reference example for documentation writers, technical writers, and anyone learning Microsoft style conventions.

## How the Guides Differ

The **Casual Guide** is written in a friendly, game-like voice aimed at players.

The **MS Style Compliant Guide** applies Microsoft Style Guide principles, including (but not limited to):

- Clear, direct language
- Consistent terminology
- Appropriate tone for technical/user documentation
- Improved readability and scannability
- Accessibility considerations
- Standardized formatting and structure

See the **Changelog** for a complete list of specific edits.

## About Spike Runner

*Spike Runner* is the sample game used in this project. The guides explain how to play it and serve as the source material for the style-guide transformation exercise.
